Python API, Telegram schema and Rust acceleration

Section titled “Python API, Telegram schema and Rust acceleration”

miniproto exposes an async Python API for Telegram MTProto. Python handles the client API and request policy, the pinned Telegram schema defines raw requests and results, and Rust accelerates selected hot paths without being required for correctness.

01Python API

Python APIs cover lifecycle, authorization, peers, updates, messages, media, sessions, retries and typed errors.

02Layer 230 schema

Generated classes expose the pinned Telegram functions and constructors, with source metadata and links to related results and errors.

03Rust acceleration

Transport framing, cryptography and selected TL constructors use native implementations when their capabilities are available, with supported Python fallbacks.

Start with an in-memory session

Section titled “Start with an in-memory session”

Keep credentials outside source control. This call uses in-memory storage and does not save bot authorization after shutdown. Encrypted SQLite sessions require a constructor key or MINIPROTO_SESSION_KEY. The quickstart explains this before the first persistent authorization.

Lifecycle and safety

Guides explain connection ownership, retry safety, flood waits, datacenter migration, update recovery, media scheduling and cancellation.

Native acceleration

Native capabilities are checked and benchmarked. Supported Python fallbacks remain available when a native symbol or wheel is unavailable.

Reference you can search

Handwritten guides and generated Python, Telegram and Rust pages share one local Pagefind index with language, kind, module, namespace, layer and visibility facets.

Protocol SDK

`miniproto` handles Telegram's protocol. The planned `mpgram` package adds routers, filters, middleware, plugins, commands and application-level helpers.
